{# What the appliance is running with, and the sentence that explains why there is no form (SAPRS 12.3, 12.6, AIG 14's "Configuration summary"). Every value is the *validated model*, so what is printed is what the services were handed at startup rather than what a file once said (SAPRS 12.5 makes the two agree by refusing to start when they do not). Names that read as secrets go through the same redaction list the log formatter uses, and there are no secrets in `config.yaml` to redact — which is the point of 12.6's rule, and why a key that looks like one is a startup error rather than a value. The reason there is no editing is stated on the page rather than in a manual: runtime state belongs in `runtime.db` and configuration belongs in the file an installer wrote. An interface that rewrote the YAML would be an application-managed database with a `.yaml` extension (SAPRS 12.7 forbids that shape in the database; this is the same mistake wearing different clothes), and a party that changed the volume by editing a file would be a party with a loud song still playing while it did. #}
